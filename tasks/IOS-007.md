## 流程（四段，顺序执行）

### 第 0 段：合并预检（一个脚本一次跑完，不要分多轮）

一次脚本内完成并输出一行结论：三个微博脚本 SHA256 与基线一致
（基线见 IOS-003 r1 回执）；设备在线；记录基线状态——AMG pid 与
是否前台、微博 pid、SpringBoard pid、Frida 当前枚举到的设备 ID。
任一脚本哈希不一致：停、写回执。**手机处于锁屏状态：停、写回执**
（不得尝试解锁）。

### 第 1 段：AMG 一键新机（只点一次）

1. 把 AMG 切到前台（已在运行则 attach/激活；没在运行才 spawn）。
2. 用 Frida 只读遍历 AMG 界面，定位文字为「一键新机」的按钮，
   记录它的位置与所属页面；点击前本地截图存 attempt 工作区（不上传）。
3. **只点一次**：优先真实 HID 触摸点按钮中心；HID 实在点不到时，
   才允许调用该按钮自身的点击动作，且必须在回执里如实写明用的是
   程序化调用，不许冒充触摸。
4. 等完成：每约 10 秒只读观察一次——完成文案出现、AMG 进程退出或
   pid 变化、进度提示消失、SpringBoard 重启（respring）任一发生都
   记录；若发生 respring，等 Frida/设备恢复（上限 3 分钟）后继续观察。
   **等待硬上限 5 分钟**：到时仍无任何完成迹象，停、写回执交回，
   不进微博段。**任何情况下都不许第二次点击「一键新机」。**
5. 若点击后出现计划外弹窗（付费、确认框、权限请求等计划里没写的
   界面）：停、写回执，不要替用户做选择。

### 第 2 段：重新确认设备（一次只读）

重新枚举设备 ID，与第 0 段基线对比：变了就记下新 ID，微博段命令
显式带 `--device <新ID>`；没变就用默认。设备枚举不到：停、写回执。

### 第 3 段：微博（IOS-005 r3 配方，原样）

微博在运行就先用 Frida 终止 `com.sina.weibo`（本单授权，仅限该
应用，记录 pid），然后只执行一次：

```text
python weibo_browse.py --device <第2段确认的ID> --bundle com.sina.weibo --open --run --confirm-home --refresh-min 1 --refresh-max 1 --swipe-min 3 --swipe-max 5 --output-dir automation/state/attempts/IOS-007_r1-a1/out
```

程序自身流程结束在登录页即达标；遇登录墙停在该状态，不点登录、
不输凭据。程序非 0 退出或 agent lost：如实记录，不重试第二轮。
