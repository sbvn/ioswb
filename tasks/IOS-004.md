- 版本：v1 / r1

## 背景

现行执行器把 `phone-operation`、`device-attach`、`real-touch`、`spawn`
等写死在 `executor/common.py` 的 `SCOPE_DENIED_ALWAYS` 里，配置层
无法放行。本任务给手机类 scope 加一条受控通道：只有本机显式打开
总开关时才放行，其余恒拒绝项一个不动。

## 要实现的四件事

1. **配置**：新增 `phone_auto` 配置段并解析进 Config：
   - `phone_auto.enabled`：布尔，默认 `false`（配置缺省、文件缺该段、
     值非法都按 false 处理，不得报错放行）。
   - `phone_auto.allowed_scopes`：字符串列表，默认
     `["phone-operation", "device-attach", "real-touch", "spawn"]`。
   - `phone_auto.max_task_timeout_seconds`：整数，默认 900。
2. **门禁**（`executor/worker.py` 的 scope 闸门与 config 的 denied 计算）：
   - 定义手机集 PHONE_SCOPES = 上列四个。
   - scope 在 `SCOPE_DENIED_ALWAYS` 且属于 PHONE_SCOPES：仅当
     `phone_auto.enabled=true` 且该 scope 在 `phone_auto.allowed_scopes`
     内时不按恒拒绝处理；否则照旧拒绝。
   - scope 在 `SCOPE_DENIED_ALWAYS` 且不属于 PHONE_SCOPES
     （`registration`、`credential-capture`、`tool-install`、`batch-run`、
     `publish-task`、`kill`）：**永远拒绝**，与 phone_auto 无关。
   - 通过恒拒绝检查的手机 scope，还须落在有效允许集内：
     有效允许集 = `scope.allowed` ∪（enabled 时的
     `phone_auto.allowed_scopes`）。未 enabled 时手机 scope 不在
     `scope.allowed` 里，同样会被「允许集外」拒绝——两道门都要过。
   - 含任一手机 scope 的任务，执行超时取
     `min(现行超时, phone_auto.max_task_timeout_seconds)`。
3. **示例配置**：`config/automation.example.json` 补 `phone_auto` 段
   （enabled=false），`automation/source/README.md` 补一段说明：
   默认关、本机开关、云端不能打开、急停方法。
4. **离线测试**（加进现有测试套件，mock/file remote，不调真实模型、
   不连手机），至少覆盖：
   - phone_auto 缺省/关闭时，`phone-operation` 任务被拒（0 执行）；
   - enabled 且 scope 在手机允许集内时，mock 任务可领取执行；
   - enabled 时 `registration` 仍被拒、`batch-run` 仍被拒；
   - enabled 但 scope 不在 `phone_auto.allowed_scopes`（如只列
     `phone-operation` 却来 `real-touch`）时被拒；
   - 全量既有测试不回归（给出通过/跳过/失败计数）。
