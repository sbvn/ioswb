## 3. 失败原因（本机实现缺陷，不是环境）

实际命令行（脱敏）：

```text
<Electron> <DSH_INSTALL_DIR>/lib/bin.js --profile headless \
  --permission-mode workspace-write --approval-policy never \
  --patch <automation>/state/local-auth-headless.yml --json -
```

headless 启动器**只解析自己的 flag**，遇到第一个不认识的 token 就把其后全部交给 app。
本轮把启动器 flag `--patch` 放在了 app flag（`--permission-mode` 等）**之后**，于是 app 收到它并拒绝：

- `harness.stdout.log`（54 字节）：`{"type":"error","message":"unknown option '--patch'"}`
- `harness.stderr.log`：空
- 进程退出码 1；没有 `RECEIPT.md`；台账记 `attempt_harness_exit status=failed` + `attempt_failed`
- **没有发起任何模型请求**（在参数解析阶段就退出）

正确顺序应是启动器 flag 在前：`--profile headless --patch <file> --permission-mode … --approval-policy … --json -`。
