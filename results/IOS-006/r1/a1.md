## 5. 与微博流程的衔接事实（只读源码）

`weibo_browse.py` 的 `DEFAULT_DEVICE_ID` **是写死的 USB UDID，不是运行时枚举**。

- 第 32 行（值已脱敏）：

  ```python
  DEFAULT_DEVICE_ID = "<UDID-已脱敏>"  # 原文为写死的 USB UDID
  ```

- 第 135–136 行：

  ```python
  parser.add_argument("--device", default=DEFAULT_DEVICE_ID,
                      help="USB 设备 ID（默认已填入当前 iPhone）。不要使用 -U。")
  ```

- 第 235–237 行：

  ```python
  def get_device(frida, device_id: str):
      try:
          return frida.get_device(device_id, timeout=8)
  ```

- 含义：默认设备 ID 固定；程序不会在运行时重新枚举设备。若“一键新机”改变了 USB UDID，下一次 `frida.get_device(DEFAULT_DEVICE_ID)` 会失败，必须先用 `--device` 传入重新确认后的设备 ID；若只改变应用层标识而未改变 USB UDID，则设备参数不受影响。
- **本单未运行 AMG，未验证一键新机是否改变 USB UDID**；下一单执行前必须重新只读确认设备参数，不能假定不变。当前只读旁证：微博已安装，pid=0（未运行）。
