## 1. 缺陷与修法

### 1.1 原缺陷（与验收复现一致）

`executor/worker.py` 把 `published[0].task_commit` 传给整份清单的信任判断；`executor/trust.py`
的 `evaluate()` 只要这个 commit 命中 `pinned_commit` 就 `trusted=True`。
结果：**只钉住任务 A 的 commit，就会放行同一清单里的任务 B**，即使清单摘要和清单提交都不匹配。

### 1.2 修法

信任判断按范围拆成两级，`evaluate()` 旧入口改为直接拒绝：

| 函数 | 判定对象 | 作用范围 |
| --- | --- | --- |
| `evaluate_manifest(trust, manifest_sha256, manifest_commit, manifest_signature)` | 清单摘要钉 / 清单提交钉 / **清单提交**签名 | `scope="manifest"`，整份清单 |
| `evaluate_task(trust, task_commit, manifest_decision)` | 单个 task_commit | `scope="task"`，**只对该任务** |
| `evaluate()` | — | 旧入口，抛错：不再接受 `task_commit` |

关键点：

1. 清单级判定**不接受 task_commit 参数**，从 API 上关闭了「任务 commit 放行整份清单」的入口。
2. 签名只核 `manifest_commit`（最后修改清单文件的提交），任务 commit 的签名不参与授权。
3. `pinned_commit` 的语义按命中对象区分：命中清单提交 → `scope=manifest`；只命中某个 task_commit → `scope=task`。
4. `worker.py` 每周期为每个 `published` 任务单独判定；未授权的任务写一条 `task_not_trusted`（去重）后跳过，
   不会因为同清单里有别的可信任务而被顺带放行。
5. 顺带修掉恢复判定的一个误伤：`task_not_trusted` 这类非「进行中」事件不再被 `_recovery_sweep` 当成
   `recovery_required`（新增 `IN_FLIGHT_EVENTS` 白名单）。
